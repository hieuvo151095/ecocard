# ECO Design System 1.0 (Consumer)

Source: a Figma file titled **"ECO design system.fig"** (mounted read-only as a virtual filesystem for this build — no public link was provided). The file's own cover frame reads **"ECO DESIGN SYSTEM 1.0 (Consumer)"**; that is the only name given anywhere in the source, so this project is titled and organized around it. No company/brand name, logo, or app identity beyond "ECO" appears in the file — do not infer a real-world company from typeface names (Helvetica Neue, SF Pro, Roboto, Inter all appear together, consistent with a system assembled by copying frames out of several native OS kits and product screens for reference, not a single shipped product).

The file is a big (~50k node) internal UI kit covering: foundations (Color, Typography, Space, Icons/Illustrator, Logo-brand, Images, Dividers), form controls (Text field, PIN, Password, Date field, Search, Input stepper, Radio/Checkbox/Switch, Chip, Picker, Calendar, Rating, Uploader), actions (Button — 68 frames of variants, Button bar), navigation (Navigation bar, Bottom navigation "Consumer", Sidebar, Tab, Bottom bar), feedback/overlay (Modal, Overlay, Dropdown menu, Notification, Sheet, Toast notification, Tooltip, Status), plus large reference pages (System-components, Secret-chambers) that read as scratch/example space rather than shippable components — skipped per the brief.

## What's in this project

- `styles.css` — root stylesheet; imports everything under `tokens/`.
- `tokens/` — `colors.css`, `typography.css`, `spacing.css`, `shape.css` (radii/elevation/motion), `fonts.css`, `base.css`.
- `components/` — React primitives grouped by concern: `actions/` (Button, ButtonBar, Chip), `forms/` (TextField, Textarea, Search, PinInput, DateField, InputStepper, PasswordField, Checkbox, Radio, Switch, Uploader, Calendar), `navigation/` (NavigationBar, BottomNavigation, BottomBar, Sidebar, Tab, DropdownMenu), `feedback/` (Toast, Tooltip, Badge, Rating, Sheet, Overlay, Notification), `media/` (Avatar), `layout/` (Divider).
- `assets/icons/` — `icon-data.js` + `Icon.jsx` covering ~190 glyphs materialized from the file's `Icons---Ilustrator` page (arrows, actions, commerce, finance, pins/maps, files, etc). `Icon.d.ts` lists every valid `name`.
- `assets/images/` — the two real avatar photo bitmaps and the generic image placeholder bitmap found in the file (copied verbatim, not redrawn).
- `assets/brand/wave.svg` — the decorative wave graphic from the Welcome/Cover frame (a repeated `<path>` vector, safe to redraw as SVG since it's pure geometry, not a photographic asset).
- `ui_kits/consumer-app/` — a clickable mobile recreation of the Consumer app screens described below.
- `*.card.html` files next to each component/foundation — Design System tab previews.

## Intentional additions

The source defines no generic `Card`, `Tabs-panel`, or `List` primitive as a single reusable component (list rows are drawn ad hoc per screen) — none were invented here. Every component in `components/` traces to a named component set in the file (see file names above ↔ Figma set names in each `.d.ts` doc comment). `Avatar`'s initials-color mapping (5-color rotation) generalizes the file's `Avatar - Initials` "Color: 5" variant axis since the file doesn't name which name maps to which of the 5 colors.

## Caveats / what's incomplete

- **Coverage is partial, not exhaustive — 31 of 2261 Figma "component families" (variant sets) are built as real components.** That 2261 count is dominated by categories that are intentionally NOT ported 1:1, with rationale:
  - **~403 icon glyphs** (Icons---Ilustrator page, plus a ~260-flag sub-set) — these are individual symbols, not component families with states; ~190 of the highest-traffic glyphs were materialized into `assets/icons/icon-data.js` + `Icon.jsx` rather than as 400+ separate `.jsx` files. Remaining glyphs can be materialized on request by name.
  - **Internal documentation-table primitives** (`_Doc table - Table/Head`, `_Doc table - Table/Cell`, `_Doc table - Row/Action`, `_Doc table - Head/Content`, `_Header`, `_Component Type`, `_column`) — these render the file's own spec tables (the "Token name / Value" grids on the Color/Typography/Space pages) and browser-chrome documentation frames (`System-components/Safari`). They are Figma-authoring scaffolding, not consumer-facing product UI. One generic equivalent, `components/layout/DocTable.jsx`, was built to cover the recurring 2-column spec-table pattern; the Safari-chrome and misc internal wrappers were not, since no real product surface uses them.
  - **`_field wrapper` (216 variants) / `_input` (14+16 variants)** — these are the Text-field component's own internal state/shape building blocks (Format × Prefix × Suffix × Shape × State). They're already represented at the product level by the shipped `TextField`, `PasswordField`, `DateField`, `Search`, `PinInput` components, which compose exactly those states; they weren't re-exposed as separate low-level primitives.
  - **Legacy near-duplicate screen fragments** under `System-components`, `Secret-chambers`, and the `6.1/6.2 Table view Row`, `15.x Buttons - Chips/Cell`, `1. Keyboards`, `Address Bar Android/Chrome` families — these read as copy-pasted native iOS/Android reference screens (status bars, keyboards, browser chrome) kept for internal reference, not the Consumer product's own design language. Skipped per the brief's "skip pure example/demo frames" guidance.
  - **Picker, Uploader's bulk-edit zone, Table-of-content, Status** (Status page is empty in the source) — not yet ported; flag if needed.

  The 29 hand-authored production components (Button/ButtonBar/Chip, all form inputs incl. PIN/Password/Date/Calendar, navigation bars/sidebar/tabs/dropdown, toast/tooltip/badge/rating/sheet/overlay/notification, avatar, divider, doc-table) do cover every top-level family the brief called out as product-facing. Ask if you want the remaining glyphs or any specific legacy/reference family materialized — given the file's size (2261 families), this was built as "complete coverage of the real Consumer product surface," not "one file per Figma variant."
- **No real webfonts.** The file specifies Helvetica Neue as the core typeface (with Inter/Roboto/SF Pro appearing in older reference frames) but a `.fig` carries no font binaries. `tokens/fonts.css` falls back to the OS system font stack for Helvetica Neue and loads **Inter from Google Fonts** as the nearest match for the legacy Inter-styled components. **If you have the real Helvetica Neue (or your production type) files, please share them** and this will be swapped to real `@font-face` rules.
- **No logo/app icon exists in the source.** The Welcome cover frame is a plain yellow (#F8BF15) card with white type reading "ECO DESIGN SYSTEM 1.0 (Consumer)" and a decorative wave — no wordmark or icon mark. Wherever a brand mark would go, this build renders the word "ECO" in type.
- Several icon components list "Not found in the .fig" during materialization (`curved-arrow-left`, `shuffle`, `swap-horizontal`, `swap-vertical`, `trend-down`, `trend-up`) — those exist as differently-named symbols in the source; re-run icon materialization with their exact names if needed.

## Content fundamentals

- **Language:** all real copy in the file is **Vietnamese** ("Trang chủ", "Khám phá", "Đơn hàng", "Ví của tôi", "Stack spacing - Khoảng cách theo phương thẳng đứng…"). English only appears in token/spec language (labels like "Label", "Value", "Token name") and in placeholder Latin text ("Steve Jobs" sample post, "Lorem"-style filler). Treat Vietnamese as the product-facing language; English is reserved for internal documentation frames.
- **Tone:** direct and functional — short imperative labels ("Xác nhận", "Huỷ", "Xem", "Bật") rather than conversational copy. No exclamation points, no jokes, no first-person "I/we" framing in UI strings.
- **Casing:** sentence case throughout; no ALL CAPS UI labels (the only capitals seen are the file's own documentation headers like "ECO DESIGN SYSTEM 1.0 (Consumer)", which is a cover/title treatment, not a UI convention).
- **Numerals & units:** counts truncate at `99+` (Badge); currency example is `VND`; dates are `DD/MM/YYYY`.
- **Emoji:** not used in any real UI copy. A few internal Figma layer names use emoji as visual markers for documentation only (🌓 for dark-mode variants, 🧰 for a "toolbox" utilities group, ◐ marking a component's primary variant axis) — these are Figma-authoring conventions, not product content, and should not appear in shipped UI.

## Visual foundations

- **Color:** two-hue primary system — **Yellow** (`color-primary-yellow*`, brand accent, `#FFC700` core) and **Blue** (`color-primary-blue*`, `#0070CE` core) each running a 10→100 tonal ramp. The actual brand/alias tier used across components is warmer: brand yellow **`#FEC020`**, with semantic blue **`#1A94FF`** for links/focus rings, green **`#00AB56`** positive, red **`#FF424E`**/`#F53743` negative, orange **`#FF9F41`** warning. Neutrals are a dedicated Ink ramp (`gray10`…`gray100`, `#F4F5F6`→`#0E0F10`) distinct from a second "legacy" gray ramp (`#F5F5FA`…`#27272A`) still used by 1.0-era nav/tab components — both are kept as separate tokens rather than merged, since the file itself never reconciled them.
- **Type:** core typeface is **Helvetica Neue** (per the file's own Typography page: *"We use Helvetica Neue typeface for Eco design system"*); legacy components mix in Inter, Roboto and SF Pro/SF Pro Display/SF Pro Text/SF Mono from screens that were clearly copied in from real OS/app references rather than authored fresh. Type scale runs 10/12/14/16/18/20/24/28/32/48px named `font-size-x-small`→`font-size-5x-large`; weights are just three — 400/500/700; line-height is a fixed formula, **font size × 1.5**.
- **Spacing:** one linear scale — 4/8/12/16/20/24/32/48/64px — reused identically for stack (vertical, margin added below), inline (horizontal, margin added right) and inset (equal 4-side padding); the file calls out this reuse explicitly on the Space/Documentation page.
- **Backgrounds:** flat color, no gradients, no photographic full-bleed hero treatment in any component (the one full-bleed moment is the Welcome cover, solid `#F8BF15` yellow with a thin decorative wave, no photo). No repeating patterns or textures anywhere in the source.
- **Animation:** the file defines no motion tokens or keyframe specs at all — it is a static-frame Figma file. This build adds a conservative, invented `--duration-fast`/`--duration-base` + standard ease pair for interactive components (switch travel, button press) since some motion is unavoidable in real React components; treat these as reasonable defaults, not source truth.
- **Hover / press states:** components use a flat 5% black wash (`rgba(0,0,0,.05)`) for pressed/disabled surfaces rather than lightening or darkening the base hue; the brand button's "pressed" skin is a literal lighter yellow swatch (`#FECD4D` vs base `#FEC020`) rather than an opacity trick.
- **Borders & shadows:** almost all component edges are **1px inset box-shadows** (`inset 0 0 0 1px <outline color>`) rather than CSS `border` — this survives corner-radius scaling cleanly, which is presumably why the file standardized on it. Elevation is used sparingly and only for floating/overlay surfaces (tooltip, toast, dropdown menu, sheet) as soft drop shadows (`0 2px 10px rgba(0,0,0,.2)`), never on static cards or list rows.
- **Corner radii:** 4px (checkbox/toast/legacy chip), 8px (buttons, text fields — the most common default), 16px (chips, sheet card), 20px (documentation tables), 30px (pill-shaped "Round" buttons), plus a distinct 64px used only on the internal documentation frame chrome (not a product radius).
- **Cards:** the file has no dedicated "Card" component; list rows and content blocks are plain rectangles with the 1px inset-outline treatment above, no drop shadow, sitting directly on the page background.
- **Transparency / blur:** used narrowly — toast/informative surfaces sit at 90% opacity (`rgba(39,39,42,.9)`) over content, and the two overlay strengths are 40% black (standard sheet/notification scrim) and 70% black (image/media overlay). No backdrop-blur usage found anywhere in the source.
- **Imagery:** the only real bitmaps in the file are two avatar sample photos and one tiny placeholder icon — no lifestyle photography, no illustration set, no brand imagery library exists in this file to characterize a "warm/cool/grain" mood from; treat this design system as icon-and-color-led rather than photography-led until real product imagery is supplied.

## Iconography

- **System:** a large custom line-icon set (~403 glyphs total per the file's component inventory) under the `Icons---Ilustrator` page, organized into topical frames (arrows, commerce/cart, finance/cards, maps/pins, files, calendar, settings) plus a **separate full flag-icon set** (~260 country flags) and Facebook's brand glyph as a one-off. Most icons ship as a `Property 1 = Line | Filled` (or `Type = Line | Filled`) pair — outline as default, filled as the "active/selected" state.
- **Format:** native Figma vector paths (not an icon font, not emoji, not Unicode glyph substitution). This build materialized ~190 of the highest-traffic glyphs as flat SVG path data (`assets/icons/icon-data.js` + `Icon.jsx` wrapper) so consumers get `<Icon name="…">` instead of hand-drawn approximations; the remaining glyphs (mostly flags and long-tail action icons) were left unmaterialized to control build size — request them by name if a screen needs one that's missing (check `assets/icons/Icon.d.ts` first).
- **Color:** icons render in `currentColor` (single-tone), matching their usage as functional glyphs rather than colorful illustrations — the flags are the one multi-color exception in the source (out of scope for this pass).
- **Emoji/Unicode:** none used as functional icons in shipped UI; emoji only appears in Figma's own layer-naming metadata (see Content fundamentals above).
