## 🔬 1. Executive & Architectural Summary

Version 36.0 represents a pivotal leap in the **Marcus Fleet Enterprise Operating System (`.agents`)**. Previous iterations (V34 Discipline Layer and V35 Design OS) successfully introduced multi-role design reviews, token compliance auditing, and interactive Figma canvas rendering. However, when generating complex enterprise features spanning **20 or more high-fidelity screens**, single-pass LLM prompts ran into severe **output token window limits**. This forced models to compress code, omit SVG icons, truncate tables, or produce sparse placeholder prototypes rather than true product-grade designs.

**Version 36.0 directly solves this bottleneck by establishing the Modular Sequential Pipeline Architecture.** 

Instead of generating a monolithic 10,000-line HTML file in a single prompt, V36.0 breaks design generation down into an isolated, sequential **Subagent Task DAG**. Each screen is rendered into a dedicated modular file (`screens/screen_01.html`, `screens/screen_02.html`, ..., `screen_N.html`), receiving **100% of the token context budget** for uncompressed UI components, charts, depth orderbooks, and SVG vector icons. A deterministic, self-healing Python assembler (`.agents/scripts/build_design_board.py`) then dynamically parses and compiles these screen modules into a single, interactive, drag-and-drop Figma Canvas Board (`board.html`) equipped with co-scaling SVG Bezier connector edges.

## 🏗️ 2. Core Technical Innovations & Components

### 2.1. Modular Screen Generation Pipeline (`screens/screen_XX.html`)

```
.agents/specs/<feature-id>/
├── design-brief.md              <-- Phase 1: Problem framing & scope
├── design-context.md            <-- Phase 1: Active design system tokens
├── screen-catalog.md            <-- Phase 2: Flow inventory & 20 screen specs
├── screens/                     <-- Phase 2: Modular Generation Pipeline
│   ├── screen_01_splash.html    <-- Subagent Pass 1: Full token context budget
│   ├── screen_02_cold_vault.html <-- Subagent Pass 2: Full token context budget
│   ├── screen_03_spot_engine.html<-- Subagent Pass 3: Full token context budget
│   └── ... (screen_20_settings.html)
└── board.html                   <-- Compiled Master Interactive Figma Board
```

- **Isolated Token Budgets**: Each screen module file in `screens/` receives dedicated LLM output context, preventing component truncation.
- **State Inheritance**: All screen modules inherit global design tokens (`--color-accent`, `--font-body`, `--radius-md`) from `design-context.md` while remaining modular.
- **Interactive Component Isolation**: Components inside screens retain full DOM event handling (`e.stopPropagation()`) for clickability on the master canvas board.

### 2.2. Master Autonomous Assembler (`.agents/scripts/build_design_board.py`)

The self-healing Python assembler script acts as the master compilation engine:

```python
# Execution Command
python3 .agents/scripts/build_design_board.py --feature .agents/specs/024-binance-mobile-20-screens
```

#### Key Capabilities:
1. **Self-Healing Auto-Bootstrap**: If `screens/` is missing or empty when `/design.board` runs on a new feature, `build_design_board.py` automatically parses `screen-catalog.md` or `flow-inventory.md`, dynamically scaffolds starter high-fidelity screen modules, and compiles `board.html` without throwing execution errors.
2. **Dynamic SVG Bezier Connector Engine**: Automatically computes 2D spatial coordinate offsets (`x1, y1` to `x2, y2`) and renders co-scaling SVG cubic Bezier curve paths (`M x1 y1 C x1+dx y1, x2-dx y2, x2 y2`) linking 100% of artboard nodes in sequence.
3. **Live Drag & Drop Recalculation**: Injects client-side JavaScript (`updateConnectors()`) into `board.html` that recalculates connector coordinates in real time whenever an artboard is dragged across the viewport.
4. **Token Snapshot Generation**: Automatically extracts design tokens into `tokens.json` for downstream CI verification.

### 2.3. 11th Deterministic Validation Gate (`validate_modular_design.py`)

To guarantee that no LLM agent bypasses the modular pipeline architecture, V36.0 introduces an **11th automated CI validation gate**:

```python
# Validation Script
python3 .agents/scripts/validate_modular_design.py --feature <feature-path>
```

- **Check 1**: Verifies presence of the mandatory `screens/` directory in the feature workspace.
- **Check 2**: Audits that `screens/` contains valid `.html` screen module files.
- **Check 3**: Validates that `board.html` compiles cleanly from the modular screen files.
- **Enforcement**: Blocks handoff to `/develop` until 100% compliance is verified.

### 2.5. Light Mode First Mandate Enforcement

Previous designs occasionally mixed dark and light cards arbitrarily. V36.0 strictly enforces the **Light Mode First Mandate**:

- **Rule Definition**: In `.agents/design-systems/company/DESIGN.md` and `.agents/skills/design-board-renderer/SKILL.md`, all core UI screens and artboard cards MUST default to high-contrast Light Mode (`--canvas-bg: #f8fafc`, `--surface: #ffffff`).
- **Sunlight Readability**: Designed for field use and warehouse monitoring where outdoor ambient lighting demands contrast ratios exceeding `4.5:1` (WCAG AAA).

## 🛠️ 5. Troubleshooting & Maintenance

### Issue 1: Unapproved Hex Color Flagged in `validate_token_compliance.py`
- **Symptom**: `TOKEN COMPLIANCE FAILED: Unapproved hardcoded color hex codes found...`
- **Resolution**: Add the newly approved design system hex color into `FORBIDDEN_HEX_PATTERN` in `.agents/scripts/validate_token_compliance.py`.

### Issue 2: Connector Lines Misaligned on Canvas Board
- **Symptom**: SVG Bezier connector arrows do not align with artboard anchor points.
- **Resolution**: Ensure artboards maintain standard width (`390px` mobile, `640px` spec card). Run `python3 .agents/scripts/build_design_board.py --feature <feature-path>` to re-calculate anchor offsets.
